# veriforge Codebase Map

A guided tour of the implementation, public APIs, developer tools, and tests.
Each `cm://ID` link targets a stable `# cm:ID` source marker. The adjacent file
link also works in a Markdown viewer without codemap support. To jump manually,
use `rg -n 'cm:ID' src veriforge_lsp` (replace ID with the actual identifier).

Start with [AGENTS.md](AGENTS.md) for repository instructions and
[notes/](notes/) for technical documentation. This map highlights implementation
entry points; [the file inventory](notes/developer/files.md) provides more detail.
When editing code, preserve existing IDs, move markers with their implementations,
and add or update entries when important APIs or subsystems change.

## 4. Semantic Model — Core Types

- [class SourceLocation](cm://3a6e9c) ([source](src/veriforge/model/base.py)) — file/line/column span; attached to every model node
- [class VerilogNode](cm://d4f6b3) ([source](src/veriforge/model/base.py)) — base class for all model objects; provides loc, parent, serialization
- [class Module](cm://b2d4f1) ([source](src/veriforge/model/design.py)) — Verilog module: ports, nets, always blocks, instances, etc.
- [class Design](cm://5c8e7a) ([source](src/veriforge/model/design.py)) — top-level container: list of Module, Package, Interface
- [class Port](cm://9f1b3d) ([source](src/veriforge/model/ports.py)) — module port with direction, width expression, type
- [class PortDirection](cm://4e2c6f) ([source](src/veriforge/model/ports.py)) — enum: input / output / inout
- [class Expression](cm://7a5d8b) ([source](src/veriforge/model/expressions.py)) — base for all expression nodes (Identifier, BinaryOp, Literal…)
- [class Identifier](cm://1e3f2c) ([source](src/veriforge/model/expressions.py)) — name reference in an expression context
- [class BinaryOp](cm://c6b4a9) ([source](src/veriforge/model/expressions.py)) — binary expression: op, left, right
- [class AlwaysBlock](cm://2f7d5e) ([source](src/veriforge/model/behavioral.py)) — always @(sensitivity) block with body statements
- [class InitialBlock](cm://8c3a1f) ([source](src/veriforge/model/behavioral.py)) — initial block with body statements
- [class BitSelect](cm://4f3b46) ([source](src/veriforge/model/expressions.py)) — bit-select expression; RangeSelect and PartSelect in the same module model fixed and indexed slices
- [GenerateFor / GenerateIf / GenerateCase](cm://634e6f) ([source](src/veriforge/model/generate.py)) — generate blocks and genvar declarations, before elaboration
- [class Statement](cm://e3341c) ([source](src/veriforge/model/statements.py)) — base for procedural assignments, control flow, timing controls, and task calls

Other model families:

| Types | Implementation |
| --- | --- |

## 9. Simulation — Shared Infrastructure

- [class Value](cm://c8a1e6) ([source](src/veriforge/sim/value.py)) — 4-state (0/1/x/z) bit-vector; val+mask+width; shared by all engines
- [flatten_module()](cm://9f4b2d) ([source](src/veriforge/sim/elaborate.py)) — hierarchy elaboration: flatten submodule instances into flat module
- [class TimedEvent](cm://5a3c7e) ([source](src/veriforge/sim/event_queue.py)) — priority queue entry (time, seq, payload) for event scheduling
- [class EventQueueMixin](cm://8b6f1d) ([source](src/veriforge/sim/event_queue.py)) — heapq-based event scheduling shared by all 3 engines
- [class CoroutineMixin](cm://f1d5b8) ([source](src/veriforge/sim/event_queue.py)) — coroutine lifecycle for timing-control fallback (#delay, @(event))
- [class SignalDictBase](cm://6c4a9f) ([source](src/veriforge/sim/event_queue.py)) — base class for signal storage (reference engine uses dict[str, Value])
- [elaborate_generates()](cm://f97081) ([source](src/veriforge/sim/elaborate.py)) — unroll loops, choose generate-if/case branches, substitute genvars, and scope generated items for every engine
- [elaboration constant evaluator](cm://a94064) ([source](src/veriforge/sim/elaborate.py)) — evaluate parameters, genvars, selects, and constant function calls before engine execution
- [resolve_sv_imports()](cm://488174) ([source](src/veriforge/sim/elaborate.py)) — resolve imported package declarations and constants before flattening
- [packed / unpacked range normalization](cm://c5fb11) ([source](src/veriforge/sim/ascending.py)) — remap ascending and nonzero-base packed ranges; normalize memory bases and multidimensional arrays
- [SystemVerilog lowering passes](cm://201aad) ([source](src/veriforge/sim/sv_functions.py)) — system functions, event expressions, streaming targets, width casts, task locals, and two-state types
- [lower_reals()](cm://e2da99) ([source](src/veriforge/sim/reals.py)) — represent real/realtime values as bit vectors and lower real operations
- [shared readmem loader](cm://f7bb56) ([source](src/veriforge/sim/readmem.py)) — readmemh/readmemb parsing and address handling shared by simulation engines

[display_format.py](src/veriforge/sim/display_format.py) and
[severity.py](src/veriforge/sim/severity.py) implement shared display/severity behavior.
[step_harness.py](src/veriforge/sim/step_harness.py) adapts Python-driven simulation steps.
For execution order and engine differences, read [simulation model](notes/simulation/simulation_model.md)
and [simulator engines](notes/simulation/simulator_engines.md).

## 12. Compiled Cython Engine

- [Shared scalar process implementations](cm://e7a921) ([source](src/veriforge/sim/compiled/_sharing.py)) — opt-in compatible-body sharing with per-process address descriptors and independent state

- [compiled wide-value emitter](cm://901398) ([source](src/veriforge/sim/compiled/_wide_emitter.py)) — multiword values, scratch evaluation, and wide memory/signal writes above 64 bits
